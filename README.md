## 特徴

### UE の Chaos PhysicsAsset は使いません

Unity 版と同じく、**自作の Bullet 互換物理エンジンを同梱**してボーンを直接駆動します。
UE の `PhysicsAsset` へマッピングする方式は採っていません。理由は次のとおりです。

- UE の拘束は Swing1 / Swing2 / Twist の**対称制限**しか持たず、MMD のジョイントが持つ
  軸ごとの**非対称な回転制限**（`rot_min` / `rot_max`）を表現できません
- `FLinearConstraint::Limit` は全有効軸で共通のスカラ 1 個なので、XYZ 独立の移動制限も表現できません
- Unity 版は PhysX 経由の実装を一度作って捨てています（インポーター本体 3,541 行・調整スライダー 49 個 →
  現行は 1,160 行・スライダー 0 個）。同じ道を辿らない設計にしました

### 物理エンジンは移植元とビット単位で一致します

物理エンジンは Unity 版の C# を 1:1 で C++ へ直訳したものです。実モデル（剛体 117・ジョイント 165）を
**300 フレーム回した後の全剛体の位置・回転が、C# 版と厳密に一致**することを自動テストで検証しています。

★**一致するのはエンジン内部（`MmdPhysicsCore`）です。再生時の挙動は 3 か所で意図的に C# と変えています。**

| 変えた所 | 理由 |
|---|---|
| `PmxPhysicsBuilder::Align` は mode1（ボーン追従）のボーンに**剛体の生の姿勢**を返す | MMD の [物理演算+Bone位置合わせ] は「親ボーンの**実際の**現在姿勢」が基準。親を bind 長で作り直していると鎖が 2 種類でき、長い鎖の末端が伸び縮みします（C# 版にも同じ欠陥があります。`bAlignBonePositions=true` なら従来どおり） |
| ノード既定 `JointVelocityIterations=40` / `JointMaxCorrectionVel=30` | 13 節の鎖はジョイントの求解が末端まで届かず、解き残しが毎フレーム溜まって戻らなくなります。**この 2 つは対でしか効きません**（反復だけ／上限だけでは悪化します） |
| `TeleportResetThreshold`（既定 3 PMX 単位 = 24cm/フレーム） | アニメのループ折り返しでポーズが飛ぶと、それが kinematic 速度になって鎖を薙ぎ払います。飛びを検出したら起動時と同じ再整合を張り直します |

いずれも**エンジンのコア既定値は 0 = 従来と完全に同一**にしてあるので、上のビット一致は保たれます。
詳細と、一致させるために必要だった浮動小数点モードの設定は [docs/porting_notes.md](docs/porting_notes.md) を参照。

## 使い方

1. メニューの **Tools → MMD Physics インポーター** を開き、`.glb` を指定して **「0. .glb を取り込む」**
   （中身は UE 標準の Interchange glTF インポータです。取り込む直前に名前の全角数字を半角へ直します。
   下の「UE 上の名前は半角化されます」を参照。glTFRuntime や非推奨の旧 GLTFImporter、
   FBX 経由では座標系が一致しません）
2. 取り込んだスケルタルメッシュが対象に入っていることを確かめる
3. **「1. 物理を配線 / 再配線」**
4. 続けて **「2. マテリアルを MMD トゥーンへ変換」**
5. 続けて **「3. アクターを生成 (本体 + アニメーション + 輪郭線)」**
6. できた `BP_<メッシュ名>` をレベルへ置いて再生

【1】を実行すると `ABP_<メッシュ名>_MmdPhysics` という Post-Process Anim Blueprint と
`<メッシュ名>_Physics` という物理データアセットがスケルタルメッシュの隣に作られ、割り当てられます。

### パッケージしたビルドで物理を動かすには

**【1】の物理を配線をやり直してください。** ゲームをパッケージすると、`.glb` は UAsset では
ないので**クックされず**、配線が持っていた `C:\...` という絶対パスも配布先のマシンには
存在しません。そのままでは実行時に物理データを読めず、**エラーも出さずに揺れ物だけが
効かない**という状態になります（エディタでは偶然パスが通るので気付けません）。

そこで【1】は `.glb` から物理に必要な部分だけを抜き出して `<メッシュ名>_Physics` という
アセットに保存し、Anim Blueprint から参照させます。アセットは Anim Blueprint から参照される
ぶんビルドへ同梱されるので、配布先でも読めます。

- 抜き出すのは glTF の **JSON チャンクだけ**です。剛体・ジョイント・ボーン階層はすべて
  そちらに入っており、メッシュとテクスチャ（BIN チャンク）は物理に使いません。
  実測で元の `.glb` の **1% 程度**になります（41.6 MB → 453 KB）。
- バイト列は元の `.glb` からそのまま複写するので、`.glb` を直接読んだときと挙動は同じです。

> **⚠️ 2026-09-12 より前に配線したモデルは、このアセットが空のままです。**
> パッケージする前に各モデルで【1】を実行し直してください。空のままビルドすると、
> 実行時に原因と手順を `LogMmdPhysics` のエラーとして出します。

`.glb` のパスも設定には残りますが、**エディタでの確認用**です。パッケージしたビルドでは
機能しません。

【3】を実行すると `BP_<メッシュ名>` という Blueprint アクターができます。レベルへ置くだけで
物理・マテリアル・輪郭線・髪の 2 パス目・モーションがすべて効きます。**【2】のあとに実行してください**
（何が必要かをマテリアルから判断するため）。

```
BP_<メッシュ名>
└─ Mesh（スケルタルメッシュ）… 物理は Post-Process AnimBP で効く。モーションもここに割り当たる
   ├─ SoftPass  … 髪の 2 パス目（柔らかい毛先）。必要な材質があるときだけ付く
   └─ Outline   … 輪郭線。輪郭線を描く材質があるときだけ付く
```

### UE 上の名前は半角化されます（GLB の原本名は保持）

UE 上のボーン名・アニメーションのトラック名・モーフのカーブ名は、**全角数字を半角にした名前**になります
（例: `右人指１` → `右人指1`）。Mac でも Windows でも同じ規則です。

- **`.glb` の原本は書き換えません。** 取り込みの直前に、名前だけを直した複製を
  `Saved/MmdPhysicsImporter/<名前>/<名前>.glb` に作ってそちらを取り込みます。
  インポート元としては原本が記録されます
- 物理・表情モーフ・移動フラグの照合は、原本名（全角）と UE 上の名前（半角）の**どちらからでも**引けます
- 半角化で名前がぶつかる場合（`右腕1` と `右腕１` が両方ある等）は、取り込み時に警告を出し、
  `右腕1_2` のような一意な名前へ振り分けます。元から半角だった名前はそのまま残ります
- **理由:** UE 5.8 の AnimSequence は、ボーンとカーブの名前を Control Rig の名前検査
  （`URigHierarchy::SanitizeName`）に通します。全角数字はこの検査を**どのロケールでも**通れず `_` に潰れ、
  `右人指１`〜`３` が 1 本に衝突してトラックが捨てられます（IA では指の 28 トラックが壊れました。18 本が捨てられ、10 本が `右人指_` のような名前に潰れました）
- Content へ直接ドラッグ＆ドロップすると全角のまま取り込まれ、上の理由で指のモーションが壊れます。
  **「0. .glb を取り込む」から取り込んでください**

### Mac では起動時に LC_CTYPE を切り替えます

Mac のエディタでは、プラグインの起動時に **`LC_CTYPE` を `C.UTF-8`（無ければ `UTF-8`）へ切り替えます**
（`#if PLATFORM_MAC && WITH_EDITOR`。パッケージしたゲームや Windows には入りません）。
切り替えた結果は起動時の出力ログに 1 行出ます（`[MmdPhysics] LC_CTYPE を 'C.UTF-8' にしました`）。

- **理由:** 上の名前検査は文字の判定に `iswalpha` を使い、Mac の既定（`C` ロケール）では
  仮名・漢字が「文字ではない」と判定されて `_` に潰れます。取り込みの間だけ切り替える方式では、
  アセットを**ロードするたび**に走る検査（`RemoveBoneTracksMissingFromSkeleton`）を覆えず、
  ロード時のエラーや、カーブ編集でのエディタのクラッシュにつながりました
- `LC_CTYPE`（文字種）以外は触りません。小数点の書式など、数値の扱いは変わりません
- **既知の副作用:** エンジンの自動テスト `System::Core::Misc::Char` が
  `Locale is "C.UTF-8" but should be "C"` で失敗します（ロケールが `C` であることを前提にしたテストです）

### 取り込み先と上書き

「0. .glb を取り込む」は `.glb` を **`/Game/<ファイル名>/`** に取り込みます
（UE 5.8 の glTF 既定パイプラインが `SkeletalMeshes` / `Materials` / `Textures` のサブフォルダに振り分けます）。
メッシュは `<ファイル名>`、スケルトンは `<ファイル名>_Skeleton`、アニメーションは `<ファイル名>_Anim` になります。

- **取り込み先に既存アセットがあると、上書きしてよいかを確認します。** キャンセルすれば何も変わりません。
  同じファイル名の別モデル（別フォルダの `model.glb` 同士など）は同じ場所に入るので、上書きに注意してください
- **全角数字のボーン名を持つ旧形式のスケルトンがあると、上書きせずに中止します**
  （「旧形式のアセットです。削除してから取り込み直してください」）。上書きでは古いボーン名が残るためです。
  取り込み先のフォルダを削除してから取り込み直してください
- **旧版の「0.」で取り込んだアセットは、手動で削除してください。** 旧版は
  `/Game/<名前>/<名前>_ue/` に `<名前>_ue` という名前で取り込んでいました。今の版は `/Game/<名前>/` に取り込むので
  上書きはされませんが、古いものが二重に残ります
- **glTF インポートのサブフォルダ設定を無効にすると、アセットは `/Game` 直下に置かれます。**
  別のモデルのマテリアル・テクスチャと名前がぶつかりやすく、上の上書き確認（`/Game/<ファイル名>/` を見ます）も
  効きません。既定のまま使ってください

### コンソールコマンド `MmdPhysics.ImportPipeline`

```
MmdPhysics.ImportPipeline <.glb の絶対パス> [-Force]
```

「0. 取り込み」→「1. 物理を配線」→「2. マテリアル変換」→「3. アクター生成」を順に実行して保存します
（エディタの出力ログのコンソール、または `-ExecCmds` から使えます）。

- **既存アセットがある場合は、既定では中止して警告します。** `-Force` を付けたときだけ上書きします。
  旧形式のスケルトンがある場合は `-Force` でも中止します
- **保存するのは、このコマンドが作成・変更したパッケージだけです。** 実行前から未保存だった
  無関係のアセットは保存しません（未保存のまま残ります）。保存したパッケージはログに一覧で出ます
- 保存対象は取り込み先の `/Game/<ファイル名>/` のアセットです（IA の例では
  `<名前>`・`<名前>_Skeleton`・`<名前>_Anim`・`<名前>_PhysicsAsset`・`<名前>_Physics`・
  `ABP_<名前>_MmdPhysics`・`BP_<名前>`・`MI_<名前>_*`）。条件次第で、BC7 に上げたテクスチャ、
  GLB から取り出したテクスチャ、近似トゥーン（`SharedToon/`）、マスターマテリアル（`M_MmdToon` など）も保存されます
- 実行前から未保存だったアセットが取り込み先にあった場合は、保存せずに警告を出します
  （このコマンドが変更した可能性があるので、内容を確かめてから保存してください）

### モーション（VMD）の扱い

`mmd2gltf-gui` は VMD を **glTF 標準のアニメーション**として焼き込みます（ベジェ補間の評価・
MMD と同じ変形順・IK 解決込み・30fps）。したがって UE 標準の Interchange が
`<メッシュ名>_Anim` という `AnimSequence` として取り込んでおり、プラグイン側に VMD リーダーはありません。

【3】は、そのメッシュのスケルトンで再生できる `AnimSequence` を自動で探して
Mesh コンポーネントに割り当てます（ループ再生）。別のモーションにしたいときは、
Mesh コンポーネントの `Anim to Play` を差し替えてください。同じスケルトンの候補が複数あるときは
同じフォルダ・メッシュ名で始まる名前を優先して 1 本選び、出力ログにその旨を出します。

物理と共存します。Post-Process Anim Blueprint は再生モードに関わらず後段で必ず走り、
ボーン追従の剛体には書き戻さないため、体はモーションどおりに動いて髪とスカートにだけ物理が乗ります。

**表情モーフも【3】で繋がります。** ただしこちらは UE 側の穴埋めです。UE 5.5 の Interchange は
glTF のモーフ（`weights`）アニメーションを取りこぼすため、`.glb` にキーが入っていても
`AnimSequence` はボーンだけになります。そこで【3】が `.glb` から直接キーを読み、
モーフターゲット名と一致するカーブを `AnimSequence` へ足します
（インポーターウィンドウで指定した `.glb` を使うので、**メッシュと `.glb` の両方を指定してから**
実行してください）。同名のカーブが既にあるものは触らないので、作り直しても二重になりません。

輪郭線の太さはコンポーネントの `Outline Width Scale`（既定 0.15）で、値を変えるとその場で
反映されます。PMX の `flags` bit4 が立っていない材質には輪郭線が出ません（MMD と同じ）。
既存のアクターに手で足したい場合は、詳細パネルの「+ 追加」から `Mmd Outline Component` を
選べば、メッシュ・追従・材質ごとの輪郭線色は追加した時点で自動設定されます。

【2】を実行すると、マスターマテリアル（`M_MmdToon` / 半透明があれば `M_MmdToonTranslucent`）と
材質ごとのマテリアルインスタンス `MI_<メッシュ名>_<材質名>` が同じフォルダに作られます。
トゥーン・スフィア・`origTexture`（プリベイク前の無加工テクスチャ）は glTF の標準マテリアルから
参照されておらず、取り込み設定によってはアセット化されません。その場合は `.glb` から直接取り出して
`MMD_ExtractedTextures` フォルダへ保存します（既にプロジェクトにあるものは再利用します）。

### 取り込み経路が違うと教えてくれます

起動時に `extras.mmd` のボーン位置とスケルトンの参照ポーズを突き合わせ、
座標系が合わない場合は具体的な対処付きで LogError を出します。

### 困ったときは

| 症状 | 見るところ |
|---|---|
| 髪やスカートの揺れが荒い / カクつく | AnimBP の MMD Physics ノードの **`FixedTimeStep` が `1/60`（0.01667）**、**`SubSteps` が 2** になっているか。`1/30` だと 1 フレームあたりの内部ステップ数が 0,1,0,1,1,... と変動して更新間隔がばらつきます。細かく刻みたいときは `FixedTimeStep` ではなく `SubSteps` を増やしてください（[docs/porting_notes.md](docs/porting_notes.md) の「ソルバ既定値はノードとコアで違う」参照） |
| 揺れが MMD の 3 倍くらい速い | `Gravity` が 98（PMX 単位）になっているか。UE のワールド重力とは無関係です |
| 半透明の材質がギザギザに切り抜かれる | その材質のマテリアルインスタンスの親が `M_MmdToonTranslucent` になっているか。ならない材質は `.glb` 側の `alphaMode` が `BLEND` でなく、`extras.mmd` の `alphaClass` も `"blend"` でないということです（`alphaClass` が `"mask"` の材質は意図的に `M_MmdToon` のままにしています。下の「半透明の描画順」参照） |
| 髪の向こうの眉やまつげが見えない | その材質に `origTexture`（プリベイク前の無加工テクスチャ）があるか。出力ログの `無加工テクスチャ N` が 0 なら、`.glb` が `origTexture` を持たない古い出力です。エクスポーター（mmd2gltf-gui）を新しくして出し直してください |
| 半透明の縁が硬い / しきい値で切れる | `M_MmdToon`（Masked）側の材質は `.glb` の `alphaCutoff` でカットします。マテリアルインスタンスの `AlphaCutoff` を下げると縁が多く残ります（しきい値はマテリアルの `OpacityMaskClipValue` ではなくこのパラメータで持っています。値ごとに静的 permutation が増えるのを避けるため） |
| 髪が透けすぎる / 透けなさすぎる | 本体の髪マテリアルの `AlphaCutoff`（既定 0.5）が「不透明に描く芯」の範囲です。下げるほど不透明寄りになります（移植元 lilToon の `_SubpassCutoff` と同じ既定値） |
| 髪の房が重なると濃さが飽和する | `SoftPass` コンポーネントが付いているか。付いていないと 2 パス目が描かれません |
| 半透明の材質どうしの前後関係がおかしい | 材質の並び順（スロット順）で描画されます。モデル側の材質順を直すか、レベルでスケルタルメッシュコンポーネントの `TranslucencySortPriority` を調整してください（モデル全体 vs 他アクターの順序にのみ効きます） |
| モーションが再生されない | 【3】で作った `BP_<メッシュ名>` を置いているか（素のスケルタルメッシュを置くとアニメーションが割り当たりません）。出力ログの `アニメーション <名前>` が `なし` なら、その `.glb` にモーションが入っていない（エクスポーターの `--vmd` 無しで変換した）か、`AnimSequence` がスケルトンに紐づいていません |
| 顔（表情）が動かない | 【3】を **`.glb` も指定した状態で** 実行したか（表情モーフは `.glb` から直接読んで足しています。UE の取り込みでは落ちるため）。出力ログの `表情モーフ N 本` が 0 でも、`既存のまま N` が出ていればカーブ自体は入っています。あとは同じログの **`スケルトンへ登録 N`** を見てください（UE はスケルトンに「モーフを動かすカーブ」と登録されたものしか繋ぎません。【3】が登録とスケルトンの保存まで行います）。`表情モーフ 0 本` かつ `既存のまま 0` なら、そのモーションにモーフキーが無いか、モーフ名がメッシュのモーフターゲットと一致していません |
| 輪郭線が出ない | 【3】で作った `BP_<メッシュ名>` を置いているか（素のスケルタルメッシュを置くと輪郭線コンポーネントが付きません）。足しても出ないなら `Outline Width Scale` を上げる。その材質の PMX `flags` bit4 が立っていない場合は出ないのが正常です |
| 輪郭線が全部同じ色 | 本体マテリアルインスタンスの `EdgeColor` が入っているか確認してください。コンポーネントはそこから色を読みます |
| 表情を変えると輪郭線だけ取り残される | `MmdOutlineComponent` が毎フレーム動いているか（`Draw Outline` が有効か、コンポーネントの Tick が切られていないか） |
| マテリアルが灰色になる | 出力ログの `[MmdPhysics] マテリアルのコンパイルエラー` を確認 |
| 静止しているのに髪やスカートが揺れ続ける | AnimBP の MMD Physics ノードの **`Use Split Impulse` / `Use Joint Split Impulse`** が両方 ON か（既定 ON）。切ると位置補正が実速度に残って揺れ物にエネルギーを注ぎ続け、固有振動数で共振します。ON にしても残る揺れについては [docs/porting_notes.md](docs/porting_notes.md) の「静止しているのに揺れ続ける」を参照 |
| 髪やスカートが体に潜り込んだまま戻らない | 貫入したまま釣り合っているので放っておいても直りません。Blueprint から **`Reset MMD Physics`**（Mesh コンポーネントを渡す）を呼ぶと、剛体を今のボーン姿勢へ再整合します。モーションの切り替え直後・ループの折り返し・テレポート直後に呼んでください。PIE を止めて再生し直すのでも戻ります |
| 物理が NaN になったとログに出る | `SubSteps` を増やす。ばね定数が大きすぎる／質量が小さすぎるモデルで起きます |

## 仕組み

```
PMX ──[mmd2gltf-gui]──▶ .glb (extras.mmd に PMX 生値を温存)
                              │
      ┌───────────────────────┤
      │ メッシュ/スケルトン     │ 物理データ
      ▼                       ▼
 Interchange glTF        MmdGlbPhysicsReader
 → スケルタルメッシュ      → PmxPhysicsModel (PMX 生単位)
      │                       │
      │                 PmxPhysicsBuilder
      │                       │
      │                 PhysicsWorld (PMX 単位のまま駆動)
      │                       │
      └── FAnimNode_MmdPhysics ┘
          Post-Process AnimBP でボーンへ書き戻し
```

**設計の要点**: 物理演算は最後まで PMX ネイティブの座標系・単位のまま行い、
UE へ出す境界でだけ変換します。変換は `FMmdUeSpace` の 1 箇所に集約しています。

座標変換の導出と実測値は [docs/coordinate_transform.md](docs/coordinate_transform.md)。

## 対応バージョン

| | 状況 |
|---|---|
| UE 5.8 | **現在の検証環境。** macOS（Apple Silicon）と Windows の両方でビルド・自動テストを確認。Windows では自動テスト 28 件がすべて green で、C# 版とのビット一致も 2 モデル × 3 ソルバ構成（既定 / 駆動あり / 再生時）で確認 |
| UE 5.5 | 旧・開発環境。当時の自動テスト 20 件が green |
| UE 5.6 / 5.7 | ソース上の互換分岐のみ。**実機検証していません** |

日本語のボーン名・モーフ名は、Control Rig の名前検査（`FChar::IsAlpha` = `iswalpha`）を
通るかどうかがプラットフォームで変わります。**Mac では起動時に `LC_CTYPE` を UTF-8 へ
上げます**が、Windows は C ロケールのままでも通るため何もしません（実測）。
全角数字（０-９）はどのロケールでも通らないので、そちらは取り込み時に半角化します。

## 既知の制限

- **モデルはワールド原点にある前提です。** シミュレーションはコンポーネント空間で行うため、
  キャラクターが移動したときの慣性の持ち越しはありません。これは移植元 Unity 版から
  継承した制限です（移植元もモデル原点前提でワールド姿勢を書き込んでいました）
- **輪郭線（エッジ）は専用コンポーネントを 1 つ足して描きます。** 自動では付きません。
  レベルに置いたアクターへ `MmdOutlineComponent` を追加してください（下の「使い方」参照）。
  太さはコンポーネントの `Outline Width Scale` で調整でき、値を変えるとその場で反映されます
- **マテリアルは Unlit です。** MMD が `KHR_materials_unlit` で出力されるのに合わせた選択で、
  陰影はライト方向（`M_MmdToon` / `M_MmdToonTranslucent` の `LightDir` パラメータ）と
  トゥーンランプで作ります。そのぶん UE のシーンライトや Lumen には反応しません
- **共有トゥーン（`toon01`〜`toon10`）は同梱されませんが、無くても動きます。**
  見つからない場合はプラグインが**近似トゥーンランプを自動生成**して代用するので
  （`{モデルのフォルダ}/SharedToon/T_MmdToonApprox01`〜`10`）、ワンボタンで陰色付きの
  トゥーンまで到達します。ただし色は自作の近似値で、MMD 側の色そのものではありません。
  **MMD 側の色で完全に再現したい場合だけ** `toon01`〜`toon10` をプロジェクトへ取り込んでください。
  置き場所は自由で、あればそちらが優先されます（名前でプロジェクト全体から探します）。
  近似色の詰め方は [`Tools/make_toon_ramps.py`](Tools/make_toon_ramps.py) を参照
- **半透明材質どうしの前後関係は、材質（スロット）の並び順で決まります。** UE の半透明ソートキーは
  `Priority → Distance → セクション順` で、同じスケルタルメッシュのセクションは前 2 つが同値になるため、
  結果として MMD の材質順がそのまま再現されます。ただし
  **`TranslucencySortPriority` は `UPrimitiveComponent` のプロパティでスロット単位には設定できない**ため、
  移植元 Unity 版の `renderQueue = 3000 + slotIdx` のような材質ごとの微調整はできません
- **半透明の重なりは、髪だけコンポーネントを 2 つ使って解いています。** UE のマテリアルは
  1 枚で 2 パスを持てないため、本体（Masked＝芯と深度）と `MmdSoftPassComponent`
  （Translucent＝柔らかい毛先）に分けています。眉のような「顔に貼り付いた 1 枚」は
  自分同士が重ならないので、素のアルファでブレンドします（MMD と同じ）
- **見え方はマテリアルインスタンスのパラメータで調整できます。** `SubpassCutoff`（半透明の
  不透明サブパスのしきい値）や `AlphaCutoff`（マスクのしきい値）を出してあるので、
  再インポートせずにエディタ上で詰められます（[docs/porting_notes.md](docs/porting_notes.md)）
- **肌などの不透明な材質は、`origTexture` があっても半透明にしません。**
  移植元は `origTexture` を持つ材質を一律に半透明へ昇格させ、深度は lilToon の TwoPass が
  書いていました。UE の半透明は深度を書けないため、肌まで半透明にすると後段の半透明
  （後ろ髪など）が顔を突き抜けます。そこで**材質が使う UV 領域のアルファ分布を測り**、
  眉・まつげ・額の影のような「肌に貼り付けた半透明の材質」だけを昇格させています
  （下地の肌が深度を書くので安全）。判定の実測値は
  [docs/porting_notes.md](docs/porting_notes.md) を参照
- **テクスチャの解像度に上限は掛けません。** プラグインが触るのは圧縮設定だけで
  （色として読めない設定の修正と、アルファを使う材質の `TC_BC7` 昇格）、
  `MaxTextureSize` は設定しません。4096×4096 のテクスチャを持つモデルはそのまま
  4096 で取り込まれます。**PC 向けでは問題になりませんが、モバイルや VR 向けに
  ビルドするときは注意してください**（BC 圧縮でも 4096×4096 はミップ込みで 1 枚あたり
  約 28MB あり、モデルを数体置くとテクスチャメモリを使い切ります）。
  UE では上限はインポータではなく**プロジェクト側の Texture LOD Group や
  Device Profile で掛ける**のが作法なので、そちらで設定してください。
  なお**圧縮そのものは常に効きます** — UE のインポータは既定で BC 圧縮を付けるため、
  非圧縮のまま残ることはありません（移植元の Unity 版はここが素通りする経路があり、
  非圧縮 ARGB32 で 1 枚 170MB という状態になっていました）

- **表情モーフのアニメーションは、プラグインが `.glb` から読み直して補っています。**
  UE 5.5 の Interchange は glTF の `weights` チャンネルのトラックを**メッシュノードをスケルトンとして**
  作るため（`InterchangeGltfAnimation.cpp` の `ProcessMorphTargetAnimations`）、ボーン用のトラックと
  結合されず落ちます（素の設定で取り込み直しても再現し、`AnimSequence` はボーン 54 トラック・
  カーブ 0 本になります）。そこで【3】が `.glb` のキーを直接読んでカーブを足しているので、
  **【3】には `.glb` の指定が要ります**。UE 側が直れば、既存カーブは触らない作りなので
  そのまま素通りします。
  あわせて、そのカーブを**スケルトンに「モーフを動かすカーブ」として登録し、スケルトンも保存します**。
  UE 5.5 はこの登録だけを見てカーブをモーフに繋ぐので、登録が保存されていないと
  エディタを開き直した時点で「体は踊るのに顔だけ動かない」状態になります
  なお UV モーフ（PMX のモーフ種別 3。IA では 8 件）は UE のモーフターゲットに
  対応概念が無いため、そもそも取り込まれず、カーブも作りません
- `sphereMode: 3`（サブテクスチャ）と `ambient` / `specular` は未対応です
  （移植元 Unity 版も `ambient`/`specular` 未対応）
- **当たり判定生成（Unity 版の【3】）は対象外です**
- `SoftBody`（PMX 2.1）は移植していません（移植元でもビルダーから未使用）
- `.pmx` 直読みの検証経路（`PmxReader`）は未移植です
- 静止時の微振動は移植元から引き継いでいます
- **長い再生では、髪や腰ベルトの鎖がゆっくり伸びます。** 実測で 60 秒後に 右髪２ が 2.2〜2.9 倍、
  腰ベルト２ が 1.5〜1.9 倍（120 秒で 3.3 倍）。しっぽのような**急激な破綻は直っています**が
  （上の「物理エンジンは移植元とビット単位で一致します」の表を参照）、この緩い漏れは残っています。
  気になる場合は Blueprint から **`Reset MMD Physics`** を呼ぶと元に戻ります。
  自動テスト `MmdPhysics.Editor.ChainStability` で検出できます
